# Infrastructure preparation

This root owns the collector infrastructure used by the `soop-single-channel` production deployment. The deployment and real reboot/mTLS/backup evidence is recorded in [implementation status](implementation-status.md); Terraform validation alone does not prove those runtime behaviors or backup restorability.

Use Terraform 1.16.2 and AWS provider 6.65.0. Signed provider checksums cover Linux amd64 and Darwin arm64. Apply the rogimarble network and product roots first, then pass the VPC, public subnet, availability zone, and marble security group outputs explicitly. This root declares an S3 backend but its isolated key, backend configuration, state, tfvars, account/AMI values, plans, and secrets stay outside Git.

The AMI must pass Canonical Ubuntu 24.04 Noble GP3, x86_64, HVM, EBS, owner, and availability checks. Bootstrap installs pinned Docker CE 29.8.1, containerd 2.3.5, Buildx 0.37.1, and Compose 5.5.1 from Docker's official Noble repository. Python 3, Git, curl, util-linux (`flock` and `findmnt`), and checksum-pinned Node 22.23.2 support the deployment validators and helpers. It verifies and enables the AMI's preinstalled deb or snap SSM agent. It prepares only the top-level `/opt/rogi-collector/app`, `/etc/rogi-collector`, `/run/rogi-collector`, `/srv/rogi-collector`, and `/usr/local/lib/rogi-collector` layout.

Bootstrap installs a persistent Docker metadata guard and IMDSv2 uses hop limit 1. Collector migrate and role units require the guard. Terraform attaches but never formats or mounts the encrypted retained data EBS. For the authorized first deployment, verify the selected new volume has no filesystem before creating one and record its UUID outside Git. Never format a volume that already contains a filesystem. Replacement hosts mount the existing UUID. The runtime host-ready unit checks the exact mount, UUID, tmpfs secrets, modes, and ownership before creating PostgreSQL, Redis, or spool directories or starting containers.

The collector intentionally has an ephemeral public IPv4 for outbound SSM, registry, and package access. It has no public ingress or DNS record. Marble reaches collector v1 mTLS RPC over private addressing, and the only inbound rule is TCP 7443 sourced from the marble security group. PostgreSQL and Redis remain unexposed. A future private-subnet/NAT design can remove the public address.

Collector images are published to private GHCR by the trusted GitHub Actions release workflow and consumed only by immutable digest. Terraform creates no registry and grants no ECR permissions. The privileged deployment job stores only its short-lived, packages-read job credential in the dedicated registry Secrets Manager entry while SSM runs. The host creates a root-only Docker config under `/run` for the pull command and removes it on success or failure; it stores no human PAT or persistent registry login. PostgreSQL and Redis use reviewed upstream digests.

Before applying the GitHub delivery role trust, read the repository OIDC customization endpoint's complete response rather than projecting only legacy fields. When immutable subjects are enabled, use its returned immutable `sub_claim_prefix` plus the exact `:ref:refs/heads/main` suffix as a private Terraform input. Do not copy repository or organization numeric IDs into this public repository, and do not replace the exact subject with a wildcard. The manual `delivery-diagnostics` workflow prints only the public bounded claims `sub`, `aud`, `ref`, `job_workflow_ref`, and `repository`; it never prints the JWT.

Run `terraform validate` and the mock-provider `terraform test` before a credentialed plan. Mock applies are in-memory and never mutate AWS. Export the private saved plan to JSON and run `infrastructure/tools/reject-data-ebs-destroy.py`; malformed plans and every EBS deletion or replacement fail. Collector deployment evidence and remaining acceptance checks are recorded in [implementation status](implementation-status.md). Cross-product readiness and cost review are maintained in the rogimarble repository.
